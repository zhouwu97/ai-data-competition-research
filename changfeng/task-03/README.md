# 题三：配送中心选址研究档案

依据：[2025公开任务](https://www.lncu.edu.cn/cxcyxy/28215.html)。正式2026规程、真实地理/需求数据和评分尚未取得。

## 要求与未决问题

处理城市需求和地理信息，按要求用K-means确定中心分布，比较不同DC数量的服务水平与覆盖。正文包含两日送达、每日行驶约270公里的背景。

不能直接把270×2当成可保证时效的服务半径：单程或往返、路线、作业、道路距离与时间都要定义。服务目标和覆盖分母需由具体任务与可用数据确认。

## 数据前提

城市ID、需求量、坐标和坐标体系。经纬度不是公里，不能把数值差直接当运输距离。位置与需求的结合方式要解释，例如需求作为样本权重，而不是随意当第三个坐标。

如果要现实落地，还需候选站点、道路/时效、容量与成本等对应字段；规定任务能否先做简化评价要看赛规，而非自己增加硬门槛。

## 最小路线与评价

固定坐标与距离处理，按要求做K-means，对多个k计算城市覆盖率、需求覆盖率和需求加权距离，再比较服务阈值变化。

K-means优化的平方距离与覆盖率、运输成本、两日送达不是同一目标。几何中心可能不是城市，也可能不可建站。

[教学代码](../../examples/03_dc_locations.py)用虚构平面公里坐标、需求权重，比较k=1至4、半径50/100/150公里；这些半径仅用于演示。

## 继续、修复与停止条件

坐标或需求严重不可信、无法定义可解释的距离与服务评价时，先修数据或口径；预算内无法修复再停止当前路线。

没有费用可以做覆盖分析，不能宣称投资回报最优。没有道路数据应明确直线距离假设，不把它伪装成实测时效。

## 扩展与交付

根据基线暴露的问题研究离散候选站点、道路、容量、建站成本与敏感性，保留规定K-means部分。任何优化都要明确可行条件及比较对象。

交付应有需求与地理处理、中心表、城市分配、多k服务曲线、假设、敏感性、报告和图表。
