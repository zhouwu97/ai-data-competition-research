# 结果对得上，还要检查算得对

在仓库目录运行：

```bash
python scripts/check_calculations.py
python -m unittest tests.test_calculations -v
```

第一条从输入和逐条结果重算数字，第二条用手算答案与故意改错的临时副本检查它。两条命令只需要 Python 标准库；先运行教学实验，才会有待检查的 CSV。

| 题目 | 独立重算什么 |
| --- | --- |
| 预测 | 从原始需求核对实际值；按窗口重算 MAE 和 RMSE，核对已保存的 MAE。若保存了 RMSE，也核对它 |
| 仓储 | 从原始订单重算每日 EQ、EN、IQ、IK；复核排序、两组 ABC 的跨阈值边界和累计占比 |
| 选址 | 从城市与中心坐标重算最近分配、城市覆盖率、需求覆盖率、需求加权平均距离 |
| 分群 | 从运单核对客户特征、业务量分档和画像；用独立公式计算演示 k=3、规则分组的轮廓系数及两者的 ARI |

压力练习也保存了足够的逐条结果，因此同一命令会重算两种预测机制的逐窗口 MAE、按玩具仓库参数计算拣选及调位距离、选址中心的覆盖与平方损失，以及客户两期与不同种子的 ARI。客户轮廓系数始终使用第一期缩放口径；选址候选最优值在给定九个城市、相同 K 和半径下重新穷举，没有把连续中心与离散候选直接混为同一约束。

这些公式不调用建模脚本或 `sklearn.metrics`。CSV 保存六位小数，数值比较采用绝对误差 `2e-6`、相对误差 `1e-7`。

例如，把所有 MAE 除以 10，再同步指标表、汇总 JSON 和文件摘要，文件之间依然能保持一致，但这里从逐日预测重算误差会报错。测试还会故意弄错 RMSE、EN、ABC、需求覆盖率、轮廓系数及 ARI，并篡改压力预测 MAE 和客户时间 ARI；仓库原文件不会被改动。

有一个性质测试检查**中心固定时，增大服务半径不会减少覆盖**。它没有要求“重新拟合后增加 K，覆盖必然变好”：K-means 优化距离，中心也会移动，那个结论并不成立。

本次检查的是已保存结果的这些计算。基础题四其他 k 和额外初始化没有保存成员标签，因此暂不独立核对；压力练习保存了种子标签，能够重算其 ARI。连续坐标选址的全局最优证明、模型拟合过程和对账文字没有一并审计。想多核对一项指标，先保存足以重算它的逐条结果。

## 预测边界与新实验

运行 `python -m unittest discover -s tests -v` 会一并检查预测、选址权衡和真实数据的小测试，需要教学依赖。预测测试保持历史不变，改写未来销量：相同起点的预测和选模必须不变；同一检验会拒绝故意读取未来均值的函数。它检查这个入口的依赖边界，不是通用的自动泄漏审查。

选址测试用手算小例核对支配关系、预算边界与覆盖。真实时长的模型测试核对未完成标签不能训练、小时样本不足时回退总体中位数。

真实研究另有标准库检查入口：

```bash
python scripts/check_public_research.py
python scripts/check_public_research.py --output-dir outputs/my-delivery
```

它从`daily_counts.csv`核对完成量逐日实际值，从两份逐条预测重算窗口MAE；时长按全部测试对象汇总，避免窗口人数不同却简单平均。同时核对测试条数、超过360分钟的条数与MAE、两方法逐条对象一致、汇总JSON、按小时/日期/长尾诊断及报告数字。`validate_research.py`会调用这个入口，不能再把只通过教学检查理解为真实结果已检查。

该入口不重新下载原始CSV，也不从原始接单与完成时间重建每条实际时长；模型拟合、训练条数和标签时点仍由源码与模型测试核查。`tests/test_public_outputs.py`故意修改总体MAE、窗口MAE、长尾、逐条预测、对象数、诊断表及报告，检查器必须拒绝这些临时副本。

运行边界测试还覆盖GBK默认文件编码、旧成功报告后的新运行失败、60位客户业务量相同、单客户、两客户、全部特征相同，以及自有配送数据没有长尾或总体误差为0。未来需求导出检验观察日期之后的数量变化不会影响预测。

报告对应检查另运行 `python scripts/test_validate_research.py`。它按证据编号精确核对表格数字与来源链接，覆盖“错误数字仍能在别处找到”及同步摘要后的反例。方法是否合理仍需读代码与报告，不能用文件对应替代。
