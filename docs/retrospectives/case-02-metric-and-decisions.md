# 案例 02：训练更久为什么变差，怎样保留失败路线

对象：msusol 的 Kaggle Playground S6E7 项目。依据：[版本分数与运行日志](https://github.com/msusol/kaggle-playground-series-s6e7/blob/80422e8a096284748524a1407c326109a2560986/docs/plans/leaderboard.md)。截至所读版本共有 v0.1—v0.9，成绩来自作者记录。

## 作者记录的路线

以 LightGBM 建立基线，增加训练预算和特征后退步；随后换 CatBoost 并以 balanced accuracy 做早停评估。日志里，基线 OOF 为 0.9389，加预算为 0.9290，新增特征为 0.9255；CatBoost 基础特征为 0.9493。

之后分别尝试阈值调整、融合、新模型与目标编码，保留了多份负结果。v0.7 的新表示得到 OOF 0.9502；v0.9 公开榜虽达到 0.95065，作者仍区分“榜单最高”与“嵌套评估中新增收益接近零”。

## 本仓库分析

路线的价值在于实验分开命名、失败保留、决策有依据。评估指标没有对齐，训练损失继续下降也不能说明比赛目标在改善。

但换模型和换早停指标同时发生，0.9389 → 0.9493 的差值不能全部归因于修正早停。应补一个固定 LightGBM、仅更换评估指标的实验。项目采用的 0.0005 停手线是实践门槛，不是通用统计检验，也不能仅凭若干折分数宣布统计等价。

## 我们采用的实验顺序

1. 固定模型、特征与切分，先核对评分函数，保存每类召回率或各分组误差。
2. 单独测试训练预算，再单独测试新增特征，记录是大类改善还是小类退步。
3. 换模型后，重跑旧基线作为参照；阈值和融合权重只在内部训练 / 验证中选择。
4. 额外保留一份未参与选择的评估，注明探索次数。分数差小又增加成本时，允许结论是“不采用”。

## 迁移到我们的比赛

Kaggle 的主要指标与方向必须直接核对赛规。海豚杯若使用综合评分，各分项和阈值应分别记录，不能把 accuracy、F1 与综合分混写。长风杯则先区分预测误差和报告 / 展示评分：模型改善并不自动提升整份作品。

应保留一张“原方案—改动—分项结果—成本—是否采用”的决策表。失败分支不能只删除，至少写明在什么数据、指标和预算下失败，避免把一次无效写成方法永远无效。
