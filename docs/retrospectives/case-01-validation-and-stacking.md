# 案例 01：验证上涨以后，为什么仍要回查预测流程

对象：avoid137 的 Kaggle Playground S6E9 复盘。依据：[作者说明](https://github.com/avoid137/kaggle-s6e9-postmortem/blob/e156407799d789f2bb30a989a5802caec099ce5b/README.md)、[逐轮日志](https://github.com/avoid137/kaggle-s6e9-postmortem/blob/e156407799d789f2bb30a989a5802caec099ce5b/docs/experiment-log.md)。属于失败分析，不以名次作为推荐理由。

## 作者记录的路线

先检查特征信号，再建立 LightGBM，扩展模型成员并筛选融合，最后尝试更复杂的组合器。记录中，线性方案 CV / 公开榜为 0.94275 / 0.94278，非线性方案为 0.94323 / 0.94238：本地增加 0.00048，公开榜下降 0.00040。

作者还回溯了一个未归一化加权和的问题：后续裁剪与 logit 变换改变了预测排序，先前关于成员贡献的结论需重测。其主要诊断是 OOF 列来自单模型，而测试列来自多折平均；建议用重复折外预测匹配聚合方式，但没有实际验证该修复。

## 本仓库分析

这是两层问题。数值层首先应确认传递的是概率还是任意分数；流程层再确认元模型训练和推理时看见的是怎样生成的输入。二者不能用一个“CV 好看”代替检查。

作者的解释具有机制依据，但没有修复前后的受控实验，不能当作唯一已证实根因。原文关于线性组合器“免疫”的表述也不能推广为通用保证：数据漂移、预处理差异和模型选择仍可能影响线性方案。

## 可执行的改进路线

| 触发信号 | 下一步 | 决策依据 |
| --- | --- | --- |
| 融合后概率超出范围 | 回查权重归一化与变换顺序 | 明确输出语义；概率与原始分数分开保存 |
| 本地上涨、榜单下跌 | 比较训练 / 验证 / 推理的生成路径 | 同一成员清单、行序、聚合和预处理是否一致 |
| 弱单模可能有互补性 | 固定成员池，比较加入 / 移除后的总分 | 不把单模分数或回归系数直接当作成员价值 |
| 小增益反复出现 | 固定切分做成对比较，再保留独立评估 | 多次搜索的选择偏差仍需考虑 |

## 迁移到我们的比赛

海豚杯分类任务可以先做单模型，再平均合规候选的概率；只有证据支持互补性时才增加元模型。长风杯预测任务先核实指标及时间切分，不能照搬此例的 AUC 或概率断言。

最小复盘产物：一张预测生成路径表，一份固定候选清单，以及撤回结论和重测计划。本仓库没有复现这些分数；作者对榜单噪声的估计依赖采样假设，不能作为其他比赛的显著性标准。
