# 案例 03：高排名方案先处理验证对象和标签质量

对象：zlin7dev/kaggle-3，作者称 HMS 脑电分类第 3 名。依据：[方案与复现说明](https://github.com/zlin7dev/kaggle-3/blob/9d9502ba8841bcdf81d3313e7920259d4b2abe59/README.md)、[数据筛选实现](https://github.com/zlin7dev/kaggle-3/blob/9d9502ba8841bcdf81d3313e7920259d4b2abe59/scripts/filter_train.py)。本仓库未核验名次，案例不涉及医疗用途评价。

## 已读路线与证据

作者先提供患者分组的四折数据，再划分用于验证与训练的不同样本集合；最终融合频谱上的二维模型与原始脑电的一维模型。筛选脚本按投票数、同一 EEG 的标签组合与窗口重叠处理记录，验证集合还按 EEG 去重。

README 要求至少 24 GB 显存；完整配置训练包含多模型、多折及多种子。说明中的较大训练集文件名，与筛选脚本实际输出多了一个字母 c，不能直接按文档路径运行。

## 本仓库分析

最值得迁移的是先确认“哪些记录属于同一个主体”，再选择验证，而非直接照搬网络架构。标签质量分层可以回答可信标签上的性能，但也改变了验证对象；不能默认该子集代表所有真实样本。

去重与分组是不同问题：去掉重复窗口不等于主体隔离，按患者分组也不等于消除时间或设备差异。完整评估需要看实际测试场景。该仓库主要解释最终方案，不能据此编造团队全部迭代史。

## 我们建议的复现分层

| 层级 | 要解决的问题 | 应留下的证据 |
| --- | --- | --- |
| 静态审读 | 主体、标签、集合与文件名是否一致 | 字段字典和输入输出清单 |
| 小规模验证 | 分组是否真的隔离；筛选后剩多少样本 | 主体交集、行数、分组与标签分布 |
| 单模型实验 | 某一表示是否有效 | 固定切分的基线与误差分组 |
| 多模型实验 | 另一表示是否补充不同错误 | 配对预测、融合增益和耗时 |

## 迁移到我们的比赛

海豚杯企业、客户或文本数据存在同主体多记录时，先审查划分方式。长风杯需求预测若同时包含多个商品与仓库，需要按预测时点评估，并分别看主体和时间上的错误。

不要因为更干净的验证集更好看，就删除所有难样本；报告说明覆盖范围，并检查被排除记录。预算有限时先学习数据与验证设计。本轮没有下载脑电数据、运行训练或验证 GPU 需求。
