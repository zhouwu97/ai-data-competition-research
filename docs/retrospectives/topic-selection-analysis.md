# 从选题到分析：本仓库的判断与取舍

更新：2026-10-08。本篇是我们结合赛题要求和六个复盘案例给出的分析，不是获奖概率预测，也不是已经完成的实验。当前没有本届完整评分表、实际数据和团队预算；以下建议都列出适用条件和改判依据。

**我的核心判断：先选能够检验结论的题，再决定用什么技术。**

一个值得做的题，应当说清楚：谁要作什么决定，现在怎样做，我们改变了什么，怎样判断改进有效。模型新、代码多、页面好看，可以服务这些问题，但不能替代证据。

如果目标是完成第一份可复查的参赛作品，我会先把需求预测列为候选，再根据数据决定是否改选客户分群或仓储分析。这个顺序依据的是证据能否形成，不是对四个题目难度或得奖机会的固定排名。

## 1. 先翻译任务：题名不等于工作范围

长风杯2025辽宁本科生赛道的公开任务有一个容易忽略的细节：“分仓商品需求预测”的正文既要求分析全国仓库和区域需求分布，也要求预测未来两周**全国总仓的总体需求趋势**。只看题名就预测所有仓库、所有商品，会扩大工作量，却可能漏掉要求的总体趋势与区域解释。

客户分群题也不只是画散点图：任务包括整合运单与业务量、使用K-means分群、解释群体特征并提出服务与营销建议。仓储题规定了EIQ与ABC分析；选址题要求结合位置与需求，并考察不同配送中心数量的覆盖与服务。

因此，我会先把任务正文改写为“要求—输出—检查方法”三列，再选模型：

| 要求 | 最小输出 | 怎样检查 |
| --- | --- | --- |
| 解释区域需求分布 | 统一口径的区域统计与图表 | 汇总能对上原始记录；时间与单位一致 |
| 预测未来两周总体趋势 | 带日期、预测值与方法说明的文件 | 历史回测；与简单基线在同一窗口比较 |
| 识别客户群并给建议 | 客户分组、画像、策略及依据 | 数据整合正确；分群稳定；策略对应可见差异 |

上表是任务转译示例，不是官方评分表。来源是往届公开说明，不能当作2026届要求。先满足规定任务，再决定是否扩展粒度或增加系统功能。

## 2. 选题先过四道门，再比较亮点

| 门槛 | 必须回答 | 过不了时怎么办 |
| --- | --- | --- |
| 规则 | 本届要求什么、允许哪些数据和模型、提交什么？ | 补齐规程；不把往届代码当作当届规则 |
| 数据 | 字段、时间、对象、目标是否真实可用且口径一致？ | 缩小问题或换题；不能靠设想补关键字段 |
| 验证 | 什么结果会说明我们的方法没有改进？ | 设计对照、回测或验收；只有演示不够 |
| 交付 | 能否完成可重算的最小输出和解释？ | 先交付基线，再加方法或界面 |

这四道门是我们的工作判断，不是自造的官方打分权重。通过后再比较领域解释空间、清洗成本、实验成本和失败风险。没有实际数据时，我不会给出精确的“获奖分数”或难度评分。

## 3. 四个方向，我会怎样取舍

| 方向 | 我的倾向与理由 | 成立条件 | 最容易夸大的结论 |
| --- | --- | --- | --- |
| 需求预测 | 优先候选。历史数据可以模拟“当时不知道未来”，直接比较改进 | 日期与目标可信；有多个与预测任务一致的回测窗口 | 预测误差下降，就宣称库存成本下降 |
| 客户分群 | 备选。整合、画像与策略能形成完整报告，但有效性更难证明 | 客户主键与业务特征可靠；能比较规则分组和聚类 | 群体看起来分开，就宣称营销有效 |
| 仓储EIQ/ABC | 订单字段齐全、预算较短时，可以成为首选 | 订单、商品、数量和分析口径足以重算 | 分类完成，就宣称拣选效率提升了某个百分比 |
| 配送中心选址 | 有地理数据和明确服务口径时值得做 | 需求、坐标与距离口径清楚；能比较中心数量与假设 | 聚类中心就是现实中最优、可落地的仓址 |

这个顺序会随证据变化。已有高质量订单数据时，仓储分析可能比预测更稳；有物流合作方提供需求和地理数据时，选址也可能更有解释价值。

缺少仓库布局并不妨碍完成题目规定的EIQ/ABC；它限制的是对额外运营收益的证明。类似地，没有库存成本和补货决策数据，预测项目仍可比较预测误差，只是不能进一步宣称节省了多少库存成本。

## 4. 若选需求预测：分析要从时间与口径开始

我的路线是：**目标与预测时点 → 简单基线 → 多个历史窗口 → 单项改进 → 分组解释。**

首先确定预测的是销售、出库量还是需求，聚合到什么层级，预测时能知道哪些字段。没有库存或缺货记录时，销量只是可观测代理；零销量可能对应需求为零，也可能对应缺货、未营业或缺失，不能直接认定。

接着建立近期均值、同星期历史值等适合数据频率的简单基线。再检查滞后、滚动统计、日历等特征是否在预测时真正可用，比较模型时保持切分和指标一致。数据预处理也应按训练和验证边界执行，不能先看全量数据再制造“历史预测”。

我不会规定“一定要六个月数据”。所需跨度取决于周期、预测窗口和对象。最低判断是：能否形成多个未参与拟合、长度匹配任务的窗口；是否覆盖希望讨论的波动；如果要声称能预测新商品，验证是否真的包含这种情境。

总误差下降后，继续问：

- 改进来自高销量商品，还是所有群体都受益？
- 节假日、低销量和突增时段是否退步？
- 换一个历史窗口，优势是否还在？
- 额外复杂度、运行时间是否值得？

如果日期不可信、目标口径反复变化，或只能靠一个偶然窗口证明优势，我会先修数据和验证；预算内修不了再换题。增加模型数量不能解决这些问题。

## 5. 若选客户分群：漂亮的群体不等于有用的群体

K-means优化的是组内平方距离，结果受特征尺度、几何形状与初始化等因素影响。它没有直接优化利润、满意度或营销效果。因此，我会先用已有业务字段建立简单规则分组，例如频次、规模、活跃程度，再问聚类提供了什么额外信息。

如果聚类结果主要复述业务量大小，把它包装成“智能客户价值体系”说服力有限。没有利润和服务成本字段，也不能把高业务量客户直接命名为高利润客户；名称应与观察依据一致。

我会分三层检查：

1. **结构：** 群体规模、离群点和内部指标是否合理，是否出现几乎为空的群体？
2. **稳定：** 改变初始化、抽样、合理特征选择或时间窗口，主要画像是否仍能解释？
3. **用途：** 群体对应哪些实际可执行的服务差异；如有后续数据，差异是否延续？

前两层不等于第三层，更不证明因果。没有真实干预和结果数据时，可以提出营销假设，不能写成已经降低流失率。若赛题规定K-means，先完成规定方法；允许额外比较时再展示其他方法的取舍。

## 6. 海豚杯：分析赛道与应用赛道要分别选题

2026辽宁工程技术大学校赛通知对数智分析和应用创新列出的关注点不同：前者侧重数据分析、建模、可视化与报告；后者还强调需求、场景、可行性及应用展示。这是校赛通知的范围，不等于已获得全国赛完整评分表。

我的建议是：

- **分析方向：** 数据来源和目标明确时，优先做可验证的预测或分类问题。上游项目用了BERT，并不能说明我们也应从BERT开始。
- **应用方向：** 有具体使用者、可用材料和验收任务时，做边界清楚的检索或分类辅助工具，先证明一个核心环节改善。
- **宽泛平台方向：** 只有“智慧物流平台”名称、多个页面和大模型接口，而没有数据与验收依据时，不作为首选。

例如，知识辅助工具可以用同一组问题比较正确性、引用依据、耗时和失败后的处理；分类工具可以比较错误类型与工作量。多模型或多智能体的数量，不是效果指标。

## 7. 先做一次短试做，再决定投入

下表是我们的工作顺序，不是赛方规定的期限。目的不是尽快堆出最终系统，而是尽早暴露选题是否成立。

| 步骤 | 留下的产物 | 这一步决定什么 |
| --- | --- | --- |
| 翻译赛题 | 一页目标、对象、时点、输出与评价依据 | 工作范围是否理解正确 |
| 审查数据 | 字段口径、主键、日期、缺失与目标检查 | 哪些结论能做，哪些不能做 |
| 跑通基线 | 可重算的输出、运行说明与简单对照 | 是否真的具备交付条件 |
| 做一次改动 | 相同验证下的总结果、分组误差与成本 | 继续、回退还是改变假设 |
| 写报告草稿 | 两张关键图、一页解释和限制 | 每个结论是否能追溯到证据 |

一次实验没有提升，不足以换题；关键是失败原因能否在预算内解决。验证和数据问题先处理，无法取得核心字段、无法建立检查方法时再停止投入。

## 8. 我认为第一份作品的创新应放在哪里

我更看重问题拆解、数据时点、误差解释和假设检验：季节性基线究竟在哪些场景失效？客户分群是否只是业务量排序？选址结果换了需求权重后是否仍稳定？

这些问题可以做成可复查的实验，也能形成有内容的报告。它们不自动满足所有赛事的创新评分：如果赛规要求算法创新或产品创新，还应增加相应的方法对照或使用验收，不能靠包装替代。

读他人方案，最值得借鉴的是为什么做某个改动、如何比较、什么结果促使回退。把别人的最终模型搬过来，反而可能跳过这些判断。

AI可以帮助整理字段、写处理代码和提出假设，但我们必须回答：输入是什么，改了什么，和什么比较，证据在哪里，出现什么结果会推翻结论。

**当前最值得补的不是更多模型名称，而是一份本届赛题卡、真实数据审查和一次最小试做。** 上述判断有待这三项证据修正，尚未正式选定题目或运行实验。
