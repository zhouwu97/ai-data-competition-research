# 从他人路线提炼我们的参赛与复盘方法

这是本仓库基于六个案例提出的工作方法，不是任何比赛的官方规则。案例样本有限，包含高排名最终方案、普通选手负结果和不完整作品；不能据此推断某条路线必然获奖。

## 一条可执行路线

具体选题判断见[从选题到分析](topic-selection-analysis.md)：优先比较可验证性和交付条件，再决定模型；分别审查题名与任务正文、规定任务与扩展收益。

| 阶段 | 要做的事 | 进入下一阶段的依据 | 对应案例 |
| --- | --- | --- | --- |
| 选题 | 明确目标、数据时点、评分、提交与预算 | 有合法可用数据；能完成最小交付；评分能重算 | 聚合物、国内杯赛 |
| 数据审查 | 查主键、重复、主体、时间、标签与口径 | 切分模拟实际评估对象；处理步骤有输入输出 | HMS、海豚杯 |
| 基线 | 运行简单方案，保存预测、版本与分项误差 | 能重跑；结果和提交格式可检查 | S6E7 |
| 改进 | 每轮回答一个问题，比较增益与成本 | 固定对照；有独立评估；失败也有记录 | S6E7、S6E9 |
| 融合 | 比较单模、均值和必要的元模型 | 互补性确有增益；两侧预测生成方式一致 | S6E9、海豚杯 |
| 提交 | 固定候选版本，检查完整交付包 | 可从数据重建输出；格式、耗时符合赛规 | 聚合物、长风杯 |
| 复盘 | 还原决策，撤回错误结论，留下待验证问题 | 每个结论有证据、范围、后续动作 | 全部案例 |

验证设计与预处理的官方技术依据：[scikit-learn 交叉验证](https://scikit-learn.org/stable/modules/cross_validation.html)、[数据泄漏](https://scikit-learn.org/stable/common_pitfalls.html)。独立、主体重复和未来预测任务应分别考虑分层、分组与时间切分；不要把所有问题都做随机五折。

## 怎么安排实验优先级

先查目标、评分与流程错误，再做低成本表示或特征实验，最后增加模型和融合。不要把若干改动一起加上后，把总收益归给其中一个。

每轮先写假设、对照和采用条件。采用条件同时包含指标方向、分组表现、稳定性、运行成本与交付风险；阈值按本题误差波动和实际意义确定，不复制案例中的 0.0005。很多轮搜索之后，当前验证集也可能被间接拟合，换种子不能自动解除选择偏差。

建议预算分配（团队可调整）：20% 数据与验证，20% 基线与接口，35% 有对照的实验，25% 报告、演示和提交检查。对报告型竞赛，按官方评分把最后一项继续增加；这组比例仅是起步建议。

## 三类比赛怎样迁移

| 比赛 / 任务 | 先借鉴 | 需要改造 | 第一份复盘产物 |
| --- | --- | --- | --- |
| Kaggle 分类 / 回归 | 连续负结果、固定基线、OOF 与候选清单 | 评分函数、数据关系、外部数据政策、运行限制 | CV / 公开榜 / 最终结果并列；不混用排名口径 |
| 海豚杯数智分析 | 表示对比、训练折内处理、评分分项记录 | 当届题目、标签定义、综合指标、报告与答辩 | 基线—改进—失败—业务解释四项证据 |
| 海豚杯应用创新 | 领域输入、最小交付、归档与工程复现 | 用户场景、功能验收、效果与成本测试 | 任务成功率、错误案例、耗时和演示版本 |
| 长风杯需求预测 | 时间切分、简单季节基线、分组误差 | 商品 / 仓库层级、预测窗口与误差口径 | 各时段及主体误差，滞后特征可用时点 |
| 长风杯分析优化 | 可复查图表、对照和敏感性分析 | 业务成本、容量、距离、聚类稳定性 | 原策略与新策略比较；模拟和实测分开 |

## 提交前如何选方案

同时保存一个稳定基线和一个证据支持的改进候选。优先选择独立评估、成本和完整性都过关的方案；公开榜用于诊断，不把极小涨分自动认作突破。候选数量与最终提交选择以本题规定为准。

检查行序与 ID、输出范围、缺失值、指标方向、环境、数据版本和输入输出文件。阈值、权重、特征选择的学习边界要写清；报告的每个数字应能追溯到结果文件。最终包至少包含按赛规允许提交的运行说明、配置、结果与报告。

## 赛后专项复盘怎么做

赛后先保存最终版本，再用 60—90 分钟做第一轮复盘（建议）：

1. 用[决策日志](../../templates/decision-log.csv)还原关键分支，按时间写假设、证据、动作。
2. 并列基线与最终结果，拆分有效增益、成本增加和未确认的榜单波动。
3. 选三次代价最大的失败，区分数据 / 验证、实现 / 环境、方法 / 信息、交付 / 协作问题。
4. 对每个解释补“有什么证据、还有什么替代解释、最小补充实验是什么”。
5. 填[复盘报告](../../templates/postmortem.md)，只选一至三个后续动作，指定产物与完成条件。

最低学习任务：从案例 02 摘三次失败决策，从案例 05 列一份数据接口表，再用自己的小数据做一次固定切分的基线与单项改进。没有运行的部分写计划；复盘应积累可验证知识，而不是事后把所有结果解释成必然。
