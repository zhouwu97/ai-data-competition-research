# 常见术语：先用一句话理解

下面的例子主要用订单和客户。真正比赛要以数据字典为准，同一个名字在不同数据里可能有不同含义。

| 词 | 白话解释 | 例子与容易混淆的地方 |
| --- | --- | --- |
| 数据集 | 一批有组织的记录 | 一张订单表；不能把“每行”都默认当一个人 |
| 样本 | 本次分析里的一个对象 | 客户分群时一位客户一行；原始表里一位客户可有多张运单 |
| 字段 / 列 | 表里的一个属性 | 订单号、日期、数量；字段存在不等于适合进模型 |
| 主键 / ID | 区分记录的身份信息 | 客户ID用于合并；不能把编号大小当成客户价值 |
| SKU | 一种具体可区分的商品 | 同款不同规格可能是不同SKU；不一定等同商品大类 |
| 特征 / X | 用来描述对象的输入 | 订单数、业务量、交易间隔；必须解释单位与取得时点 |
| 标签 / y | 希望预测的已知答案 | 分类训练中的是否违约；聚类通常没有这种答案 |
| 模型 | 根据输入产生输出的一套规则 | 可以是线性回归，也可以是聚类；不一定是大模型 |
| 参数 | 模型从数据中学出的数 | 线性模型的系数、K-means的中心位置 |
| 超参数 | 训练前由我们设定的配置 | K-means分几组；“调参”不能偷看最终测试答案 |
| 分类 | 从已知类别的例子学习，再预测类别 | 用已标注的垃圾邮件训练分类器 |
| 回归 / 预测 | 预测一个数值或未来量 | 明天出库多少件；“回归”不只指线性回归 |
| 聚类 | 按输入相似程度分组 | 没给真实等级，让算法分客户；不自动证明业务价值 |
| 线性回归 | 给特征乘上学出来的系数再相加，预测数值 | 日期趋势与星期特征可组合成一个简单预测 |
| Ridge | 对系数大小加约束的线性回归 | 尽量降低复杂系数；不是自动避免所有过拟合 |
| DC | 配送中心 | 配送中心数量不是聚类质量分数 |
| 基线 / baseline | 用于比较的简单起点 | 最近7天均值；复杂方法要说明比它增加了什么 |
| 训练 / fit | 根据数据学习规则 | 算出中心位置、拟合系数或标准化统计量 |
| 推理 / predict | 用已学习规则处理输入 | 给新客户分组；不是重新训练的同义词 |
| 验证集 | 暂时不参与拟合，用来检查方法的部分 | 用过去训练，预测后来14天 |
| 测试集 | 最后评估或赛方给的待预测数据 | 名字可能因项目而异，要说明自己怎样使用 |
| 数据泄漏 | 用了预测当时不该知道的信息 | 把未来销量放入特征；答案泄漏会制造虚假的好分数 |
| 过拟合 | 对当前训练或反复使用的验证数据过于适应 | 一直调到验证最好，不代表换一批数据仍好 |
| 指标 | 按明确规则计算的比较量 | MAE越低越好；覆盖率要先定义分母 |
| 标准化 | 用选定规则调整特征尺度 | StandardScaler用均值和标准差；不自动让特征同等重要 |
| 随机种子 | 固定随机过程的起点 | 便于复查；一个种子的好结果不代表普遍稳定 |
| OOF | 某条训练记录由没见过它的训练折模型来预测 | 常用于Stacking；必须核对生成过程，不能只看文件名 |
| Stacking | 用多个模型的预测再训练一个组合模型 | 三模型直接取平均是均值融合，不是因此就叫Stacking |
| 消融 / 对照 | 去掉或只改变一个部分再比较 | 保持验证一致，看新增特征是否真有用 |
| 可复现 | 别人能按说明重新得到对应产物 | 要有数据口径、依赖、命令、配置和结果 |

## 同一个客户怎样从多行变成一行？

客户C001有5张运单。先按customer_id分组统计，得到订单数5、总业务量120件、距离最后一次交易3天，再把这一行交给聚类。直接把5张运单分别聚类，分析对象就变成了运单，不再是客户。

## 编号不是价值顺序

K-means返回0、1、2，只是在给组起代号。换一次初始化，这些代号可能交换。要读各组的原始字段统计，才能解释群体；不能把2自动叫作最高价值。
