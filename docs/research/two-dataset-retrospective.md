# 两套物流数据的研究复盘：拿到数据后要做什么

这次最需要纠正的是：后期大量工作围绕预测模型比较展开，没有持续把每轮实验接回一个明确的业务决定。用户要求研究深度学习是合理方向；研究组织上的失误，是没有始终说明它要解决哪类错误、结果会改变什么行动。

下次拿到数据，先写清楚：**帮助谁，在什么条件下做什么决定；从数据中取得什么证据；用什么对照判断这个决定是否更好。** 再选择统计方法、特征和模型。

本页把已得到的认识与下次的建议路线分开。数据来源、实验状态和本机记录入口集中在[证据说明](evidence.md#两套物流数据研究复盘的依据)；本页不重新训练，也不新增收益结论。

整体关系见[可编辑研究路线图](../../figures/research_decisions.drawio)，内容源与调用方式见[MathModel配图入口](../experience/paper-figures.md)。两套数据是分别分析、分别验证的分支，不是把两套数据拼成同一个预测任务。

## 1. 两套数据分别服务什么目的

| 数据与题目 | 要帮助做的决定 | 当前能研究的对象 | 结果的用途 |
| --- | --- | --- | --- |
| 仓储拣选流水：题二仓储运营优化 | 重点管理哪些商品，怎样分组、安排货位与拣选 | 已提供明细样本中的订单、商品、数量、储位及日期 | 解释作业压力，提出差异化策略，并比较方案产生的工作量 |
| 智能分仓商品日记录：题一需求预测 | 为未来14天商品量提供准备参考 | `qty_alipay`已记录成交件数；全国记录总量与有观测的商品日分别评价 | 输出数量参考、误差与适用对象；有库存、交货周期和成本以后，再研究补货决定 |

仓储中的短期作业量预测可以作为辅助研究，不能替代每日EIQ/ABC与拣选策略。题一有商品日记录，也不等于已有分仓销量：目前行为表没有地区或仓字段，Cost中的仓代码不能补出历史区域需求。

## 2. 仓储流水：从作业压力走到方案比较

目的：**弄清工作量来自哪里，找到值得调整的商品和作业方式，再检验调整是否减少工作。** 下表是建议路线，已有数据核查不等于后续策略已经全部执行。

| 步骤：要解决什么 | 得到什么 | 用来做什么 | 怎样判断能否继续 |
| --- | --- | --- | --- |
| ① 数据能代表哪些业务？ | 表关系、订单主键、日期覆盖、重复与缺失处理说明 | 确定使用哪批订单，防止把样本当全仓、无记录当零 | 同批订单汇总可对账；缺口保留状态，两表只在可比范围关联 |
| ② 仓库忙在哪里？ | 每日订单数、件数、单均品项数和储位数，以及高峰来源 | 区分订单处理、重复取货和搬运压力 | 从明细重算同一日统计；异常先解释，不凭阈值删掉 |
| ③ 哪些商品值得重点管理？ | 数量与频次双口径ABC、每日变化、重点商品清单 | 选择货位、补货或批量处理的候选对象 | 频次按不同订单等明确单位计算；全期分类用于描述，后续方案用前期数据确定 |
| ④ 哪些订单适合一起处理？ | 商品共拣与储位重合关系、候选分组规则 | 尝试减少重复到访，同时识别新增分拨工作 | 记录相同订单、计划时间窗和载荷条件；现有拣选时间不能自动当成订单提前可用时间 |
| ⑤ 分组、路径、储位改变后是否更好？ | 基准、单项改变和组合方案的配对结果 | 决定保留哪项调整，避免把组合效果全归给ABC | 各方案处理相同订单，固定其他条件；同时计算节约与新增工作 |
| ⑥ 未来需要提前准备多少？ | 可选的订单量、件数预测及分日期误差 | 提供作业量参考；有可靠工时参数后再讨论人员需求 | 同一预测时点和窗口比较中位数等基线；不能用模型名代替效果判断 |
| ⑦ 形成什么建议？ | 采用、暂不采用、条件不足的方案及理由 | 让仓库管理者知道能试什么、还需补什么 | 每项建议能接到对应记录、对照结果和适用条件 |

EIQ分别看订单、品项、数量。例如一单拣1,000件与1,000单各拣1件，总件数相同，订单处理与走访压力可能差很多。具体计算要区分：EQ是一单件数，EN是一单不同品项数，IQ是一个品项的件数，IK是涉及该品项的不同订单数。拆储位行不能直接当成更多订单或更多品项。先完成题目要求的每日分析，再用较长周期判断哪些变化值得采取行动。

双口径ABC应产生不同的策略假设：高频商品值得研究如何减少重复到访；数量大但低频的商品需要检查批量搬运与补货；两者都高的商品列为重点候选。分类不是收益证明，昨天A类、今天B类也不意味着必须搬货，还要看后续访问、补货与搬迁代价。

一个可以被推翻的假设是：**按储位重合度合并订单，会减少重复到访，但可能增加分拨。** 用前段数据确定规则，再让后段同一批订单分别接受原规则与新规则。若减少的访问不值得新增分拨，就不采用；若只在部分载荷条件下有利，就限定使用条件。现有历史已经查看过时，这只能称历史回放；下一次比赛应提前留出后段评价。

缺少真实平面图时，仍可完成EIQ/ABC和访问计数等分析。储位访问计数是工作量的代理指标，不能改名为实际步行距离；由编码推断的布局、速度和工资只能用于明确假设下的距离及成本情景。不能从这种情景直接宣布现场提效或全年节省金额。

## 3. 智能分仓：先弄清基线错在哪里，再增加模型

目的：**利用预测时已经知道的商品记录，为未来14天成交量提供数量参考。** 预测对象、时间边界和评分对象先固定，模型再进入比较。

| 步骤：要解决什么 | 得到什么 | 用来做什么 | 怎样判断能否继续 |
| --- | --- | --- | --- |
| ① 预测什么，一行代表什么？ | 日期—商品唯一性、成交目标、商品覆盖和字段说明 | 区分成交件数、下单件数、金额及未知商品日 | 核对原始记录；不拿未来支付、浏览等实际值当预测输入 |
| ② 数量变化来自哪里？ | 商品数量、同一批商品的成交变化、零值与购物节分布 | 区分商品组成变化与单品变化，选择需要解释的对象 | 比较不同历史队列时说明覆盖，不能用未来是否有记录决定当时预测资格 |
| ③ 简单方法在哪些地方失败？ | 中位数、均值、同星期基线的逐窗口、商品及日期误差 | 确定下一轮需要解决的错误，而非先选网络名称 | 固定相同日期与真值集合；普通日期与已知活动日期分别观察 |
| ④ 哪种输入或设置可能解决错误？ | 一个明确假设及单项对照 | 检验成交变化、历史行为表示、商品差异或模型设置 | 例如比较中位数锚点、小特征集、较小网络或不同轮数；不同时全改后再归因 |
| ⑤ 对照能否跨时间成立？ | 开发选择、后段窗口与固定种子结果 | 决定是否替换基线，还是只保留研究候选 | 预处理只拟合历史，训练标签不越预测起点；查看后段后不再称新盲测 |
| ⑥ 数量预测支持什么行动？ | 预测值、误差、覆盖和失效情景 | 提供备货或资源准备参考，并说明何时需要人工补充信息 | 要声称补货成本改善，另需库存、交货周期与损失依据；预测误差不能替代业务评价 |

例如，普通日期偏高，可以先检验近期大促是否抬高了均值，以及从中位数出发做有限修正是否更合适；商品变化没被捕捉，可以比较历史浏览、加购、支付的变化和相互关系。这里只是在提出待验证假设，不能把“听起来合理”写成已有改善。未来行为未知，任何转化或趋势特征都必须只用截止日以前的记录。

全国记录总量直接建模；共享商品模型让多个商品共用参数，但只在未来有记录的格子上检查商品误差，并报告覆盖。不能按未来有记录的商品名单筛选预测后求和，冒充当时可运行的全国预测。更多商品也不会增加独立促销年份。

## 4. 本轮究竟得到什么，改变了哪些决定

| 已有事实或结果 | 对研究决定的影响 |
| --- | --- |
| 仓储明细与汇总覆盖不同，只能在交集校验；有无记录日期 | 使用明细样本开展结构分析；不拼成完整季度全仓，也不直接把无记录日解释成停运 |
| 两表交集一致，不提供抽样机制或代表性证明 | 不再用“抽样”推导ABC稳健、波动被放大或预测偏悲观 |
| 智能分仓仅99个商品全期有记录，缺商品日原因未确定 | 保留未知标签，报告覆盖；预测目标限定为已记录成交，不声称已解决潜在需求与区域分仓 |
| 全国MLP后段日MAE为5,736.10件，中位数为5,346.63件，六窗仅一窗改善 | 本轮不替换中位数；优先排查模型起点、输入与容量，不直接扩大网络 |
| 商品MLP后段MAE为10.0495件/商品日，中位数为10.0030件/商品日，六窗两窗改善 | 历史行为汇总的局部收益不足以支持采用；保留失败结果，重新提出具体表示假设 |
| 后段三个种子的整体误差都更高 | 负结论并非只因“六窗均不退步”的标准严格；也不能据此否定所有深度学习 |

题一中位数主参照由开发期选定，以上没有按后段成绩改选。开发仅一个固定种子，后段三个种子；全量审计已查看日期、覆盖和极值。准确定位是这三种固定设置的MLP没有胜出，不是已经穷尽深度学习。完整数字见[实际报告](../../research/smart-demand/results/report.md)。仓储原有多轮研究也应保留局部改善与不稳定的区别，不能把反复查看的历史当成不断增加的新证据。

## 5. 失误怎样改成下次的做法

| 这次的问题 | 下次怎样改 |
| --- | --- |
| 预测比较逐渐占据研究主线，业务行动跟进不够 | 先写目标句；仓储优先完成每日EIQ/ABC与策略依据，预测单独说明用途 |
| 容易按模型清单推进，实验与具体错误连接不够 | 每轮先写“观察到什么错误、为什么这个改变可能解决、出现什么结果就放弃” |
| 新MLP从近28日均值起步，却缺少从主中位数出发的修正对照 | 把模型起点作为明确对照；比较本身有效，但不能遗漏可能影响判断的设置 |
| 固定容量与轮数、行为只作7/28日均值汇总，排查不足 | 先检验小特征、小网络和训练轮数，再研究行为变化；不把失败主要归因于数据量 |
| 开发期以普通日期为主，后段含双11/双12，选型只用一个种子 | 提前检查时间覆盖，记录普通与活动日期的取舍；种子用于检查随机性，不当作新数据 |
| 数字与代码核验较充分，行动与代价验证不足 | 计算正确以后，把主要精力用于同订单或同未来窗口对照，并解释新增成本与业务用途 |
| 多轮失败后，继续方向不够集中 | 明确保留什么、淘汰什么，下一轮只检验能改变决定的少量问题；没有增益就保留基线 |

这些做法不要求比赛前把所有复杂模型跑一遍。先让一个简单方案贯通“数据—发现—行动—评价”，再针对暴露的问题扩展。

## 6. 下次开赛怎样使用本页

先读题目正文和评分要求，用已有[赛事卡](../../templates/competition-card.md)写明必须交付什么，再填一句：

> 我们帮助【使用者】，在【时间、资源与数据条件】下决定【行动】；先从数据获得【信息】，与【原方法或简单基线】比较；若【评价结果】成立就采用，否则保留原方法或修改假设。

仓储例句：“帮助仓库作业负责人比较分组规则，用前期订单形成候选，在后期相同订单与载荷情景下比较重复访问和分拨；没有足够收益就保留原规则。”题一例句：“提供未来14天已记录成交量参考，比较中位数与一个针对明确错误的改进；若后段误差和主要场景没有支持改进，就保留中位数。”它们都是研究目标示例，不是已实现收益。

然后按本页对应表推进。每项主要输出能接上这三个问题即可：**发现了什么？所以准备改变什么？什么证据支持或否定这个改变？** 图表用于解释，模型用于比较，最终报告交代决定、依据和条件。实验与取舍继续记入已有[实验记录](../../templates/experiments.csv)和[决策日志](../../templates/decision-log.csv)，不另建一套流程。
